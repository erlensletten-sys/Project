# Instruction Document for LLM: Product Feature Analysis & Workflow Guide

Product: Tripletex

Purpose: To extract every available feature, how it works, how to set it up, and how it fits into workflows, in clear, structured, and professional language.

Audience: Small-medium business owners, finance professionals, accountants, or integration developers.

## PHASE 1: FEATURE INVENTORY – 'What It Does'

Goal: List every feature the product offers, grouped by module or function.

**LLM Prompt Template:**

Act as a product analyst. Provide a complete list of features/modules that [Product Name] offers. Group features under categories such as:
1. Accounting & Bookkeeping
2. Invoicing
3. Payroll
4. Project Management
5. Inventory/Logistics
6. Automation & Integrations
7. Mobile App
8. Reporting & Analytics
9. API / External integrations

Include:
- Feature name
- Short functional description
- Whether it is optional or included in base tier
- Whether it integrates with other modules

Expected Output:
A categorized list of all features, in a table or bullet list, clearly indicating scope and modularity.

## PHASE 2: FEATURE EXPLANATION – 'How It Works'

Goal: For each feature identified in Phase 1, describe in detail how it works in practice.

**LLM Prompt Template:**

For each feature in the [Product Name] platform, provide a detailed explanation of:
- What it does
- How it functions (step-by-step)
- Real-world usage scenario
- Who typically uses it (accountant, employee, manager, etc.)
- Required setup or prerequisites (if any)

Expected Output:
A feature-by-feature deep-dive, like mini-manuals for each module.

## PHASE 3: SETUP & ONBOARDING – 'How To Start'

Goal: Guide the user through initial setup and configuration of the tool.

**LLM Prompt Template:**

Provide a detailed onboarding guide for [Product Name] that includes:
- Account creation and login
- Company profile setup
- Choosing a pricing plan or modules
- Adding users and roles
- Connecting bank and external services
- Importing old accounting data
- Customizing document templates and preferences
- Initial data validation steps

Expected Output:
A checklist-style onboarding guide and setup flow, with clear instructions and decision points.

## PHASE 4: DAILY USE CASE WORKFLOWS – 'Using It Day-to-Day'

Goal: Explain typical daily workflows using the system.

**LLM Prompt Template:**

Outline daily/weekly/monthly workflows in [Product Name], including:
- Who performs each step
- What screens/functions are used
- Typical inputs/outputs (invoices, time logs, reports)
- Integration with other modules

Cover workflows like:
1. Creating and sending an invoice
2. Recording expenses and receipts
3. Running payroll
4. Submitting tax/VAT
5. Registering time and assigning to projects
6. Reconciling bank transactions
7. Viewing profit/loss or project margin reports
8. Handling a late payment or dunning process

Expected Output:
Narrative step-by-step usage stories, showing how users interact with the system for key tasks.

## PHASE 5: TECHNICAL INTEGRATION & API

Goal: Map the product’s external communication capability (APIs, plugins, integrations).

**LLM Prompt Template:**

Explain how [Product Name] integrates with external systems (CRM, POS, eCommerce, banks).
- List native integrations and partners
- Describe use cases (e.g., invoice sync, data exports)
- Summarize the API capabilities (data models, auth, rate limits)
- Provide examples of workflows automated via API or Make.com
- Include links to API docs if possible

Expected Output:
Clear documentation of integration options, API endpoints, and external triggers/inputs.

## PHASE 6: REPORTING & ANALYTICS

Goal: Summarize the tool’s analytics capabilities and reporting logic.

**LLM Prompt Template:**

Describe the reporting and analytics capabilities of [Product Name]. Include:
- Standard reports (e.g., P&L, balance sheet, VAT)
- Custom report builder features
- Support for formulas (e.g., LOOKUP, SUMIF)
- Ability to schedule or export reports
- Example use cases: monitor profit margin, analyze project spend, compare periods

Expected Output:
Detailed view of what insights are available, how to customize reports, and how to automate recurring analytics.

## PHASE 7: FINAL OUTPUT CONSOLIDATION

Goal: Compile everything into one structured, professional reference document.

**LLM Prompt Template:**

Using all previously provided data, generate a complete documentation output that includes:
- Executive summary
- Full feature list and descriptions
- Setup and onboarding process
- Workflow walkthroughs
- Integration/API guide
- Reporting tools and logic

Format as a professional product reference, suitable for onboarding new staff or evaluating platform fit.
